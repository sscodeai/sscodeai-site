# ai-project-skill-maker

`ai-project-skill-maker` は、AI コーディングエージェント向けに **長く使えるプロジェクト保守用 skill と instruction bundle** を生成する meta-skill です。通常のプロジェクト文書を作るのではなく、将来の AI セッションがリポジトリを理解し、既存のスタイルに沿って変更し、適切な検証を実行し、プロジェクトの意図を保ち、生成物や注意が必要なファイルを不用意に編集しないための、プロジェクト専用の保守ガイドを作ります。

## Links

- Repository: [`sscodeai/ai-project-skill-maker`](https://github.com/sscodeai/ai-project-skill-maker)
- License: Apache-2.0
- Runtime: Node.js scripts + platform-neutral な Markdown templates
- Install 先: `~/.codex/skills/ai-project-skill-maker`

特定のプラットフォームに固定しない設計です。標準テンプレートは AI project maintainer skill として使え、reference adapters により Codex skill、`AGENTS.md`、`CLAUDE.md`、Cursor rules、`.github/copilot-instructions.md` などの形式へ展開できます。

## 2 つの mode

| Mode | 対象 | 入力 |
|---|---|---|
| **Genesis Mode** | まだ十分なリポジトリ上の証拠がない新規プロジェクト | 言語と locale の好み、目標と非目標、想定ユーザー、技術的な制約、ドキュメントのトーン、品質基準、リリース方針、最初のマイルストーン |
| **Repo Mode** | 既存リポジトリ | `README*` / docs / contribution / changelog / license、`package.json` と lockfiles、build・test config、CI workflows、scripts・tests・entry points、generated-file signals、commit / style signals |

Genesis mode の出力は、開発者が宣言した意図と推奨標準を記録した day-one maintainer skill です。ただし、それらを観測済みのリポジトリ事実であるかのようには扱いません。Repo mode の出力は、観測されたプロジェクト事実に基づく長期保守用 maintainer skill になります。

### Language and Locale Setup

Genesis mode では最初に、作者がどの言語で考えたりレビューしたりするのが得意かを確認します。作者が希望すれば、以降のインタビューと生成される project-facing references もその言語と locale profile に寄せます。たとえば日本語プロジェクトでは `です・ます`、`だ・である`、技術文書向けの混合スタイルを選べます。希望がない場合のデフォルトは英語です。

## Evidence Model

生成される project references では、主張を次の 4 種類に分けます。

| Label | 意味 |
|---|---|
| `observed_fact` | リポジトリファイル、コマンド、CI、テスト、メタデータ、履歴から得られる証拠（可能な限りファイルパスを引用） |
| `declared_intent` | maintainer が明示した目標、制約、好み |
| `recommended_standard` | プロジェクト種別に合うため選ばれた標準 |
| `inferred_assumption` | 情報が不足している中での慎重な仮定 |

## Generated Output

```text
project-maintainer/
  SKILL.md
  agents/openai.yaml
  references/
    project-intent.md      project-map.md        architecture.md
    coding-standards.md    content-style.md      workflows.md
    verification.md        release.md            generated-files.md
  scripts/health-check.* optional
```

生成される Markdown ファイルには、手書き用の保持ブロックが入ります。

```markdown
<!-- BEGIN USER RULES -->
<!-- Add durable project-specific rules here. This block is preserved on refresh. -->
<!-- END USER RULES -->
```

refresh workflow では、この marker の中身を保持します。

## Scripts

```sh
node scripts/collect-repo-signals.mjs /path/to/repo > repo-signals.json
node scripts/draft-project-config.mjs --repo /path/to/repo > config.json
node scripts/validate-config.mjs --input config.json --mode repo --strict
node scripts/render-project-skill.mjs --input config.json --output ./my-project-maintainer --strict
node scripts/validate-project-skill.mjs ./my-project-maintainer
```

platform-specific instruction files を生成します。

```sh
node scripts/render-adapter.mjs --input config.json --adapter agents --output .
node scripts/render-adapter.mjs --input config.json --adapter claude --output .
node scripts/render-adapter.mjs --input config.json --adapter cursor --output .
node scripts/render-adapter.mjs --input config.json --adapter copilot --output .
```

`--init-config genesis|repo` で starter config を、`--print-schema` で schema を出力できます。fresh session で評価するための forward-test prompts は `references/evals/forward-tests.md` にあります。

## Current Capabilities

- genesis mode（intent-first な新規プロジェクト）と repo mode（観測された repository signals）
- author interview と生成 references のための language / locale setup
- config schema、example configs、strict config validation（evidence labels と repo fact citations を確認）
- project maintainer skill folder の render と validate
- user-authored rule blocks を保持する refresh workflow
- ローカル Codex personal skill の installation と installed-content self-check
- Codex skills、`AGENTS.md`、`CLAUDE.md`、Cursor rules、`.github/copilot-instructions.md` 向け adapter guidance
- Astro / documentation sites、TypeScript・Node OSS projects、documentation-heavy projects
